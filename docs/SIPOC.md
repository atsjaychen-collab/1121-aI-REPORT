## 邊界與資料品質

- 本課程指定的流程是「選擇需求 → 比對方案 → 生成推薦」。第一版於瀏覽器端使用 HTML、CSS、JavaScript，不串接 Supabase。
- 目前的 `research/travel-data.json` 可支援景點／活動情報展示，不足以證明旅行社販售方案存在。缺少方案時輸出應稱為「情報提案」或「探索結果」，不得稱為可訂購行程。
- 活動日期及景點特色以來源支持內容為限。資料中的來源更新時間、查詢日期與有效期間需保留；不明者標「待確認」。
- 過期資料應降低可見度並提示重新核對，不應以舊資料作確定推薦。使用者可點入來源確認最新資訊。
- 顧客只提交推薦所需偏好；聯絡資料非推薦必填。第一版若未實作安全的伺服器端收件與隱私流程，諮詢 CTA 僅提供旅行社公開聯絡方式或預填需求文字供旅客自行傳送，不在本機儲存或送出個資。
