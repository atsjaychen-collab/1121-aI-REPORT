# PRD｜旅行社獲客網站（第一版）

專案：AI 台灣旅遊情報員 × 智慧行程推薦網站  
文件／週次：獲客網站產品需求／2026-11-21  
負責角色：網站規劃  
版本／更新日期：v1.0／2026-11-21  
目標客群：親子／情侶／熟齡／全部  
資料狀態：含待確認；旅遊來源資料非模擬資料  
接收角色：網站工程師、驗收員

## 1. 產品目標

以每週旅遊情報吸引潛在旅客，協助旅客快速縮小選擇、看懂方案差異，並以清楚的推薦依據引導諮詢。衡量第一版是否達成目標，以可完成需求輸入、結果可理解、來源可追溯及諮詢入口可使用為主；不設定沒有基準資料支持的轉換率目標。

**CCI 對應：**核心是快速找到適合行程；明確收集旅遊對象、預算、天數、風格；解決行程太多、難比較、不知如何選擇。

## 2. 使用者

- **親子旅客：**需要比較自然觀察、湖岸或節慶情報；網站提醒兒童年齡、推車、預約或現場限制需另確認。
- **情侶旅客：**需要依景觀、拍照、節慶或慢遊等偏好探索；推薦理由須明示哪些是行程配對建議。
- **熟齡旅客：**需要檢視步行、休息、無障礙等資訊；不得僅憑熟齡標籤推定體能或可及性。

## 3. 範圍

### 第一版包含

- 以 HTML、CSS、原生 JavaScript 建置靜態、響應式網站原型。
- 週報精選情報與三類客群入口。
- 偏好表單、前端資料比對、結果卡片、比較／清除條件及諮詢行動呼籲。
- 旅遊事實的來源、查詢日期、待確認與過期狀態呈現。
- 靜態 JSON 或 JavaScript 資料檔作為資料輸入；第一版不加入 Supabase。

### 第一版不包含

- 會員帳號、伺服器端個人化、線上付款、訂位、團位即時查詢、後台 CMS、即時天氣／交通 API。
- 未經核實的旅行社商品、售價、折扣、可訂狀態或行程保證。
- 未完成隱私及安全設計的個資表單資料收集與儲存。

## 4. 頁面與主要區塊

1. **首頁／週報入口：**品牌與服務說明、每週情報摘要、親子／情侶／熟齡快速入口、「開始找行程」CTA。週報情報標示週次及查詢日期。
2. **需求選擇區：**旅遊對象、每人預算上限（TWD，可略過）、天數、旅遊風格；欄位附單位和簡短說明。
3. **推薦結果區：**結果數、排序／篩選提示、方案或情報卡片、推薦原因、符合／部分符合項目、價格與計價單位、來源、查詢日期、待確認及資料過期標示。
4. **詳細介紹／諮詢區：**景點或活動介紹、限制、官方來源連結及諮詢 CTA。若沒有實際旅行社方案資料，CTA 文案為「詢問此主題」或「洽詢行程規劃」，不得顯示訂購或立即報名。
5. **無結果狀態：**明確說明找不到符合方案，提供逐項放寬條件、清除篩選及諮詢入口；不可靜默改用不符合的資料。
6. **頁尾：**資料更新說明、非即時／非保證聲明、隱私用途／保存期限／刪除方式（如有收集資料）、來源入口。

## 6. 推薦邏輯

推薦分兩階段：

1. **必要條件篩選：**若資料明確標示行程天數、價格及計價基準，套用使用者指定的天數與每人整趟預算上限。缺少必要欄位時，該方案不得標示為「符合預算／天數」；可在「資訊不足，需洽詢」區展示，並說明缺少什麼。使用者未填的條件不作篩選。
2. **偏好排序：**在符合硬條件的候選項中，依客群適配、旅遊風格標籤及內容主題排序。來源直接支持的適配可標「資料明載」；研究員推論或一般內容配對標「行程建議／待確認」。相同分數維持穩定排序，不虛構「最適合」百分比。
3. **資料有效性：**活動需在選定旅遊日期（如有）仍有效，且活動日期來源已查核；超過有效期即排除出未來推薦。若旅客未提供出發日期，只呈現尚未結束且期程有來源的活動並提示再次確認。景點若營運狀態、營業時間或交通未核實，明顯提示「出發前確認」。
4. **結果分組：**「符合條件」、「部分符合或資訊不足」、「無符合方案」。情報資料不能偽裝成可售套裝商品；未取得實際商品資料前，結果標題使用「旅遊情報提案」。
5. **預算定義與比較：**統一使用新臺幣（TWD）每人整趟行程總額作為搜尋上限。旅行社方案需記錄每人／每團、每日／整趟、含稅與否、包含／不包含項目及價格有效期限。未提供同一基準者不可直接比較或判定在預算內；顯示「價格待確認」。不把景點免費、活動免費或其他未經來源核實的假設納入方案價格。

### 找不到符合方案時

顯示「目前資料中找不到符合全部條件的方案」，並列出造成無結果的條件（例如預算、天數或風格）。提供旅客自行選擇的調整按鈕：放寬預算、改變天數、移除風格條件、檢視部分符合／資訊不足項目、清除條件，或洽詢旅行社。每次調整前保留原始條件可恢復；不自動放寬條件，也不保證調整後一定有方案。

## 7. 資料欄位

### 旅遊情報／方案欄位

| 欄位 | 型別／格式 | 必要性 | 說明 |
|---|---|---|---|
| id | 字串 | 必要 | 穩定唯一識別碼。 |
| recordType | 列舉 | 必要 | 景點、活動或旅行社方案。 |
| title、description | 字串 | 必要 | 名稱及有來源支持的介紹。 |
| region | 字串／物件 | 建議 | 縣市、地區；未知時留空，不自行推測。 |
| audienceTags | 陣列 | 建議 | 親子、情侶、熟齡；需附適配依據及驗證狀態。 |
| styleTags | 陣列 | 建議 | 自然、節慶、慢遊等；由資料或編輯核實。 |
| durationDays | 正整數或 null | 方案必要 | 套裝行程整趟天數；景點／活動情報可為 null，不作方案天數匹配。 |
| priceAmount | 數字或 null | 方案必要 | 價格；不得以虛構數字補值。 |
| currency | 字串 | 方案必要 | 第一版限定 TWD。 |
| priceUnit | 列舉 | 方案必要 | 每人／每團、每日／整趟。比較預算時要求「每人、整趟」。 |
| priceIncludes、priceExcludes | 字串陣列 | 方案建議 | 費用包含及不包含項目。 |
| priceValidUntil | 日期或 null | 價格建議 | 過期後顯示「價格待確認」，不沿用舊價格。 |
| eventStart、eventEnd | ISO 日期或 null | 活動必要 | 官方活動日期；景點可為 null。 |
| sourceName、sourceUrl | 字串／網址 | 事實必要 | 來源名稱及可追溯連結。 |
| queriedAt | `YYYY-MM-DD` | 事實必要 | 本專案資料查詢日期。 |
| sourceUpdatedAt | 日期時間或 null | 建議 | 來源提供的更新時間，保留原值／時區。 |
| validUntil | 日期或 null | 建議 | 內部確認的資料有效期限；未知時為 null 並標待確認。 |
| verificationStatus | 列舉 | 必要 | 已驗證、待確認、過期。可按欄位細分狀態。 |
| pendingItems | 字串陣列 | 必要 | 尚未確認的票價、開放、交通、動線、節目等。 |
| suitabilityBasis | 字串 | 客群標籤必要 | 說明客群適配依據；推論需明確標待確認。 |
| isSimulated | 布林值 | 必要 | 模擬案例、行程、價格必須為 true 且在介面醒目標記。 |

### 偏好欄位

- `audience`：親子／情侶／熟齡。
- `budgetMaxTwdPerPersonTrip`：可空，非負數；單位為 TWD／人／整趟。
- `durationDays`：可空，正整數。
- `styleTags`：可空陣列。
- `travelDate`：第一版可不提供；如未實作日期欄位，不假設出發日期。

第一版不要求姓名、電話、電子郵件、生日、健康資料或精確年齡來生成推薦。若諮詢需要聯絡資訊，另行取得明確同意並告知用途、保存期限及刪除方式；未完成該流程不得收集或持久保存。

## 8. 資料狀態與呈現

- **已驗證：**顯示來源、查詢日期及適用內容；不代表即時營運狀態。
- **待確認：**在卡片與詳情中顯示「待確認」徽章，逐項列出待確認內容。價格、日期或安全／可及性等關鍵欄位待確認時，不可宣稱方案完全符合。
- **過期：**顯示「資料可能已過期／請確認最新公告」及舊查詢日期；活動已結束即移出未來推薦。價格超過有效期限即不再用於預算篩選。
- **模擬資料：**卡片標題及資料欄均標「模擬資料」；第一版若使用模擬旅遊方案，絕不可與真實情報混排而不作區隔。
- **無來源或查詢日期：**不得展示為已驗證旅遊事實；轉為待確認或不上架。

## 9. 響應式版型與無障礙

- 採手機優先設計，支援窄螢幕單欄表單與卡片；較寬螢幕可將篩選器與結果並列。
- 在手機上保持欄位標籤、按鈕及來源連結易觸控；不以橫向捲動呈現主要內容。
- 使用語意化 HTML、表單標籤、鍵盤可操作控制、可見焦點狀態及狀態文字；顏色不是唯一的狀態提示。
- 文字、價格單位、資料日期及待確認提示在常見縮放下仍可閱讀；錯誤訊息對應欄位並提供修正方式。
- 版面斷點由實作依內容測試決定；斷點數值屬實作決策，待確認。

## 10. 隱私、安全與技術限制

- 第一版只使用 HTML、CSS、JavaScript；不加入 Supabase，不在前端放密鑰、存取權杖或供應商機密。
- 需求偏好只在當次瀏覽器互動中用來比對，不寫入 URL、分析工具、Local Storage 或 Git 樣本。
- 若提供諮詢，優先使用旅行社已公開的聯絡方式；非必要不收集個資。任何聯絡表單必須先定義用途、保存期限、刪除方式與負責單位，此項在正式上線前待確認。
- 外部連結標示來源；不得未經授權複製來源圖片、商標或多媒體。
