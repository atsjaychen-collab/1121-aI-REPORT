# 網站原型功能驗收紀錄

專案：AI 台灣旅遊情報員 × 智慧行程推薦網站
文件／週次：首頁及推薦原型驗收／2026-11-21
負責角色：驗收員（單一 Agent 執行）
版本／更新日期：v1.0／2026-11-21
目標客群：親子／情侶／熟齡
資料狀態：已查核官方來源；含待確認及明確標示的模擬行程／價格
接收角色：專案負責人、網站工程師

## 驗收環境與方式

- 檔案：`index.html`，以本機 HTTP 預覽，桌面瀏覽器互動驗收。
- 窄版畫面：以約 548 px 瀏覽器可視寬度檢視單欄版面；CSS 手機斷點為 680 px。
- 測試資料：頁面內 6 筆清楚標為模擬資料的行程構想／示範價格，另有 1 筆官方情報資料；均不是旅行社正式商品。
- 旅遊內容依 `research/travel-data.json`、`research/sources.md` 及 `docs/weekly-report.md`；活動日期另抽查觀光署官方活動頁，查詢日期為 2026-11-21。

## 功能驗收

| 項目 | 結果 | 實測證據／限制 |
|---|---|---|
| AC-01 偏好、預算、天數、風格 | 通過 | 表單可選親子／情侶／熟齡、每人預算、1／2／3 天與多選風格；預算標示 TWD／人／整趟並可略過。 |
| AC-02 價格與天數硬條件 | 通過 | 輸入 TWD 8,000／人／整趟及 2 天時，展示 3 筆符合、4 筆部分符合／資訊不足；資訊提案因缺天數、價格被列入資訊不足，不判定預算符合。模擬價格明確區隔真實報價。 |
| AC-03 推薦理由與來源 | 通過 | 展開阿里山卡片可讀到客群依據、景點事實、待確認清單、觀光署連結與查詢日期 2026-11-21；週報區也提供活動官方連結。 |
| AC-04 待確認／模擬／過期 | 部分通過 | 卡片明示模擬資料或官方情報、待確認事項、日期來源。程式會依瀏覽器當日日期排除已結束活動；本次驗收日未透過修改系統日期實測已結束活動排除。 |
| AC-05 無結果與手動調整 | 通過 | 輸入預算 TWD 1,000 及 3 天，顯示 0 筆符合，逐項指出限制並提供提高預算、取消天數、移除風格、清除及洽詢操作；未自動放寬。 |
| AC-06 資料不足呈現 | 通過 | 野柳資料卡標示官方情報、非套裝商品、價格未提供及需洽詢；預算／天數被指定時列為資訊不足。 |
| AC-07 響應式／鍵盤／狀態 | 部分通過 | 窄版約 548 px 截圖顯示單欄表單與卡片，主要操作可見；結果區使用 `aria-live`，按鈕及表單為原生語意控制。未完成完整鍵盤逐項遍歷及多尺寸縮放／溢位自動檢查。 |
| AC-08 HTML／CSS／JS 及安全 | 通過 | 單一靜態 `index.html`；未使用 API、外部套件、Supabase、密鑰、Local Storage、Session Storage 或偏好上傳。 |
| AC-09 諮詢與隱私 | 通過 | 沒有聯絡表單或個資欄位；介面說明偏好只供本次配對，不儲存。複製按鈕以目前表單條件生成文字，瀏覽器顯示「諮詢需求已複製」。 |
| AC-10 事實與承諾用語 | 通過 | 活動日期帶來源與查詢日期；頁面明示交通、開放、票價及蝶況待確認，沒有可售團位或結果保證。 |

## 實際操作紀錄

1. 預設條件顯示 7 筆可瀏覽項目；清除條件後恢復預設表單。
2. 設定預算 TWD 8,000、2 天，並勾選自然景觀；結果依硬條件分組，推薦說明顯示模擬價格、天數及風格配對原因。
3. 設定預算 TWD 1,000、3 天；出現明確無結果訊息和可手動調整按鈕。
4. 展開阿里山介紹，來源與待確認項目可讀；按「複製諮詢需求」後出現成功狀態文字。
5. 窄版畫面以單欄顯示；未進行實體手機、平板或無障礙輔助科技測試。

## 待確認／正式上線前

- 旅行社正式商品、價格、計價條件、包含／不含項目及價格效期尚未提供；目前僅能示範規則式比對，無法驗收可售行程與真實預算推薦。
- 旅遊資料查詢日期為 2026-11-21；實際出發前應重新查核來源及活動公告。
- 諮詢聯絡方式、個資用途、保存期限、刪除方式與負責單位待正式上線前確認；本原型不收集或保存個資。
- 尚未實測窄螢幕下所有卡片、瀏覽器縮放、鍵盤全流程及螢幕閱讀器；目前只完成可視寬度約 548 px 的畫面抽查。
- 活動過期排除邏輯依當日日期運算，尚未藉日期模擬／跨日情境實測；活動資料新增時由旅遊研究員核實來源及有效日期。
