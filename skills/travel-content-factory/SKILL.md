# Travel Content Factory

將研究資料轉為可供審稿的旅遊內容套件。只依可追溯來源撰寫旅遊事實，分開呈現已核實資訊、推論、待確認與模擬資料。預設交付草稿；未經內容負責人審核及使用者明確授權，不發布或推送到正式網站、社群、郵件或其他外部渠道。

## 觸發條件

當使用者要求執行下列一項或多項工作時使用本 Skill：旅遊資料研究、週報編輯、簡報大綱／頁面內容、影片腳本／分鏡、旅行社網站情報或活動頁內容更新。使用者可只要求部分階段；只完成指定範圍，並說明上下游缺項。一般旅遊建議、網站程式功能開發或沒有內容製作需求的工作不觸發本 Skill。

## 輸入資料

開始前從使用者提供內容及專案檔案確認可用資訊，不要預設不存在的資料：

- 週次、研究截止日、地區／季節／主題、目標客群（親子／情侶／熟齡）。
- 既有來源清單、研究 JSON／CSV、前版週報與尚待回答問題。
- 品牌語氣、發布渠道、篇幅、簡報目的／頁數、影片平台／長度，以及網站頁型／欄位。
- 商品資料（如有）：價格與計價單位、適用日期、包含項目、可售狀態、條件及官方來源。缺少商品資料時只產出情報內容，不得把景點／活動情報說成旅行社商品。

若關鍵輸入缺失，先完成不依賴該輸入的研究或草稿部分，並在成果及待確認清單標明缺口；只有會改變交付方向的缺項才詢問使用者。

## 工作步驟

1. **盤點與界定：**讀取專案 `AGENTS.md`，定位 `research/`、`docs/weekly-report.md` 或 `weekly-reports/`、`presentations/`、`video/`、`website/` 及 `handoffs/` 的現有素材。確認要求的客群、期間、輸出與審核者；避免覆寫已核准內容，除非使用者要求更新。
2. **研究與核實：**對可變或可能不確定的旅遊事實使用可用的網路搜尋／官方第一手來源；以來源名稱、直接連結和查詢日期（`YYYY-MM-DD`）記錄。若沒有網路或來源不可用，沿用可查的既有來源並揭露未能重新驗證之處，不推測補值。將官方原文事實、編輯推論和待確認事項分開；保存來源更新時間／有效期間及更新風險。
3. **建立研究交付：**需要新增研究時寫入 `research/`，包括摘要、客群關聯、逐項事實與來源對照、查詢日期、資料狀態及待確認清單。不得把推論偽裝成官方標籤。
4. **編輯週報：**依旅客可理解的方式整理標題、摘要、客群分眾、行動呼籲、來源註記、查詢日期與待確認事項。可售價格、營業時間、團位、交通班次、天候及活動每日安排若無來源支持，標「待確認」並避免肯定敘述。
5. **簡報內容：**依目的整理逐頁主訊息、頁面文字、視覺需求及來源註記。每頁主張須回連研究來源；標出建議、示意畫面或模擬數據。若只要求大綱，交付大綱即可，不自動產生或發布簡報檔。
6. **影片腳本：**依平台及長度產出旁白／字幕、分鏡、素材需求、行動呼籲、來源與查詢日期、素材授權狀態及待確認項目。未確認授權的素材標「待授權」；旁白、字幕和畫面不得超出來源支持範圍。
7. **網站內容更新：**把核實後內容映射到既有頁面欄位或建立草稿。推薦需說明依據、來源、查詢日期、適用對象及限制。對過期活動移出未來活動推薦；舊價格不再當作現價；其他更新風險顯示「資料可能已過期／待確認」。不要新增未核實事實或暗示即時狀態。若需要改動網站程式，僅在使用者要求程式實作時處理。
8. **交接與審稿：**依專案慣例把階段、版本日期、負責／接收角色、資料狀態和待確認事項記入 `handoffs/`。所有對外文字標示為草稿／待審核；附上審稿重點和可追溯證據。只有收到明確審核核准及發布授權後，才執行所授權的發布動作，且發布後回報實際結果。

## 不可妥協的品質規則

- **保留來源：**每項外部旅遊事實、價格、日期、營業時間、交通、政策或天候主張皆需來源名稱、可追溯連結及查詢日期。來源必須能支持相鄰主張；不要只在文件末尾列無法對應主張的泛用來源。
- **模擬資料分離：**合成旅客、偏好、行程、價格、推薦結果、成效數字及示意畫面須在標題或資料欄明確標示「模擬資料」，不得和真實情報混淆。
- **不編造易變資料：**缺來源的價格、活動日期、名額、時刻、交通、營業資訊不得補造。明確標「待確認」；無法查證時如實記錄原因及負責確認者（若已知）。
- **審核後發布：**檔案建立、簡報輸出、網站內容更新皆不是「已發布」。未審核內容維持草稿；外部發布需使用者明確授權。不可宣稱未完成的發布、查詢、轉檔或工具操作成功。
- **隱私與憑證：**只收集推薦必要的偏好。不得把客戶個資、密碼、API Key、存取權杖或供應商機密寫入公開案例、前端、範例、紀錄或版本控制。諮詢資料收集需說明用途、保存期限及刪除方式；缺少安全收件方式時不收集或儲存個資。
- **限制與適用對象：**分眾建議須列依據；熟齡／無障礙標籤不保證所有動線可及。不得保證天候、交通、景點開放、活動結果或成團。

## 輸出成果

依使用者要求選擇必要檔案；未指定時依專案既有結構建立，避免重複另一份同用途檔案：

- 研究：`research/` 研究紀錄及來源對照。
- 週報：`weekly-reports/` 週報草稿；若專案已以 `docs/weekly-report.md` 管理，沿用該位置。
- 簡報：`presentations/` 大綱、頁面腳本或素材清單；實體簡報檔只在要求時建立。
- 影片：`video/` 腳本、分鏡及素材清單；實際影音成品只在要求且工具可用時建立。
- 網站內容：`website/` 草稿或現有網站內容欄位更新；發布狀態另行標示。
- 交接／審稿：`handoffs/` 或 `qa/` 記錄，含已完成、待確認、來源與審核狀態。

每個交付標示專案、文件／週次、負責角色、版本／更新日期、目標客群、資料狀態及接收角色。若採不同格式，至少保留來源日期、資料狀態及待審核標示。

## 品質驗收

交付前逐項確認並在 QA／交接記錄留下結論：

1. 每個可查證主張都有對應來源、連結與查詢日期，來源支持該主張。
2. 官方事實、建議／推論、待確認與模擬資料清楚區隔。
3. 沒有自行補造價格、日期、團位、時刻、數量、成效數字或行程承諾。
4. 易變或逾期資料有有效期間／更新提醒；已過活動不當成未來活動宣傳。
5. 週報涵蓋指定客群；簡報每頁訊息清楚；影片敘述和素材符合來源／授權；網站呈現推薦依據、來源和限制（只驗收使用者要求的交付範圍）。
6. 個資與憑證未外洩，諮詢收集方式符合最少蒐集原則。
7. 所有輸出處於「草稿／待審核」或有明確核准記錄；沒有把未執行的發布說成成功。

## 失敗與中止處理

- **搜尋或來源連線失敗：**停止將新事實標為已核實。可用舊資料需保留原查詢日並標示未重新確認；列出失敗來源、受影響內容與重新查核需求。
- **輸入資料不全／矛盾：**不要自行裁決相互矛盾的日期或價格。標示衝突來源、原始值及需確認的角色；完成不受影響的內容後交付。
- **工具或轉檔失敗：**保留已成功產出的文字草稿，明確列出失敗工具／步驟、錯誤或限制及未完成檔案；不得把預期成果當成實際檔案。
- **來源不能支持文案：**刪除或降級該主張為待確認／建議，並說明所缺證據；不要用二手猜測填補。
- **發現個資或疑似秘密：**停止散佈並排除受影響素材；若疑似已提交，依組織憑證輪替程序處理，不能聲稱刪檔即已失效。
- **審核／授權未取得：**停止外部發布，保留草稿並列出需要誰核准的內容。遇到使用者明確要求的發布以外的外部動作，不自行擴大授權。

## 在 Codex 中使用與測試

`skills/travel-content-factory/` 是本專案指定的教材交付路徑，Codex 不保證自動掃描根目錄的 `skills/`。依目前 Codex Skill 文件，repo 範圍的自動探索路徑是 `.agents/skills/`；個人範圍是 `$HOME/.agents/skills/`。Codex 以 YAML frontmatter 的 `name` 和 `description` 判斷可用性，依請求載入指令；技能檔變更會自動偵測，若清單未更新則重新啟動 Codex。其他 API／執行環境需明確註冊 Skill 目錄，不能假定同一個目錄規則通用。

在本專案手動驗證而不安裝：

1. 開啟 `skills/travel-content-factory/SKILL.md`，直接在新提示中要求「請依此 Skill 使用 `docs/weekly-report.md` 做來源追溯與待確認事項小型 QA，勿發布」，並附上該檔及 `research/sources.md`、`research/travel-data.json`。
2. 檢查回覆是否保留來源日期、指出待確認、沒有填造資料，且明確保持草稿狀態。這是人工行為測試，不能證明 Codex 自動探索成功。
3. 若要測自動探索，先複製整個資料夾到 `.agents/skills/travel-content-factory/`，在 Codex 新工作階段確認 `$travel-content-factory` 可用，使用同一週報測試；測完可移除暫存副本。要讓 repo 長期啟用則把技能安裝／維護於 `.agents/skills/`，或將教材路徑和該位置設計為可同步的單一來源，不要讓兩份內容長期分歧。
4. 若本機有 Python，執行 `python <skill-creator>/scripts/quick_validate.py <skill-folder>` 檢查名稱、YAML frontmatter 與未完成範本。若 Python／驗證器不可用，回報未執行；可人工檢查 frontmatter 必須含 `name`、`description` 且名稱與資料夾一致。格式檢查不等同內容品質或自動觸發測試。
